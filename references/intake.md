# 开工前问一次

看完图、过了骨架关，发**一条**消息，把要用户定的事一次问完，每项都带推荐，用户回 ok 就照推荐做。没回不动手。

## 1. 能不能做

能做就一句「这只能做」。只有这几种情况停下来说：

| 图里有 | 为什么不行 | 怎么说 |
|---|---|---|
| 三条以上的腿 / 触手（章鱼、蜘蛛） | 骨架只有两只手、两只脚 | 「它的 8 条腿这副骨架没有，硬套会像一颗球放在几根管子上（试过）。换一张两手两脚的图？」 |
| 长手长脚、人形比例 | 手只能整只绕肩膀转，没有手肘、膝盖 | 同上，说清楚是缺关节 |
| 四条腿着地的动物 | 前腿会被当成手挂在肩膀上 | 同上 |
| 要走路、跑、手指动 | 没有腿的关节、没有手指 | 「走路要给腿加关节，是另一件大活；先做站着的这套？」 |
| 没有脸、脸是贴图（比如屏幕脸） | 眼睛、嘴是模型的零件，要会眨眼会笑 | 问用户脸要不要按两眼一嘴做 |
| 好几只角色在同一张图 | 一次只做一只 | 问先做哪一只 |

衣服、围巾、帽子、背包这类贴在身上、不用自己动的东西都能做（围巾是一圈 ＋ 垂下来的一条，帽子是一颗贴在头上的零件）。

## 2. 有毛还是没毛

看原图表面：

- **有毛**：边缘是绒的、毛茸茸，看得出一根根的毛（毛绒玩具、羊毛毡）。→ 推荐有毛。
- **没毛**：边缘干净、光滑、哑光或微亮（搪胶、软胶、陶土、黏土、塑料公仔）。→ 推荐没毛。
- 分不清，或用户想比：两种都做，并排放（同一份形状，只换皮）。

告诉用户差别：有毛更软更暖，但每帧要画几十层，手机上最吃性能（慢的手机会自己减毛）；没毛轮廓和高光清楚，像玩具，手机上最顺。

## 3. 要哪些动作

默认六个，不用写代码（每只只调「想」那只手的角度）：

1. 开场：背对着，转过来，跳起来笑
2. 平时：呼吸、眨眼、头和眼睛跟着鼠标 / 手指看，没人动就自己左右看一眼，偶尔扑一下手
3. 想：一只手举到头侧挠头，头歪着，眼睛往上看
4. 干活：点头，两只手错开着拍
5. 好了：跳起来笑一下，回到平时
6. 点它：跳起来笑

再问「还想加什么动作？用大白话说就行，比如挥手、点头说是、摇头说不、睡着打呼、转一圈、害羞捂脸」。能做的范围（骨架有的关节）：转身、歪、蹲、跳、压扁拉长、转头点头歪头、眼睛看哪、眨眼、笑、嘴大小、两只手往外张往上抬往前。做不了的照实说（走路、手指、尾巴甩、衣服飘）。

## 4. 出哪几样、放哪

- 网页（实时 3D，一个页面，或接进现有网站的某一块）
- App（Expo：大的那只实时 3D，小的地方播帧图）
- 两个都要（推荐：同一个模型，多出一份 App 组件）

再问放在哪：网站的哪个路径 / 哪个项目、App 是哪个项目。项目里看得出来的（比如服务器上只有一个 Expo 项目）就自己查，写成推荐，不问。

## 消息模板

> 这只能做。我打算这样做：
> - **皮**：有毛（图里边缘是绒的）。要换成没毛、或两种并排比，说一声。
> - **动作**：开场转身、平时、想、干活、好了、点它跳。想加别的就用大白话说，比如「挥手」「睡着打呼」。
> - **出**：网页 ＋ App（Expo）。网页放 `<路径>`，App 放 `<项目>` 的 `<文件夹>`。
>
> 回 ok 我就开始，大约 <N> 小时。

时间：新做一只（量图 → 建模 → 对原图改到像）大约 1–2 小时（2026-10-16 盲测从零做企鹅用了 35 分钟，零件多、有毛的会更久）；加一个动作 20–40 分钟；换皮 10 分钟；出帧图 5–15 分钟（有毛的软件渲染慢）。
